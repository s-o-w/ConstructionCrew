# gh CLI: requesting a Copilot code review on a PR

Researched against `gh` version 2.96.0. Re-verify if you're on a materially
newer version -- this is undocumented CLI behavior, not a stable public API.

## What's actually documented

`gh pr create --help` documents no Copilot-specific value for `--reviewer` --
just ordinary human/team handles.

`gh pr edit --help` documents it explicitly:

    --add-reviewer login      Add or re-request reviewers by their login.
                              Use "@copilot" to request review from Copilot.

    # Request a review from GitHub Copilot
    $ gh pr edit 23 --add-reviewer "@copilot"

The GitHub Copilot code-review bot's login resolves to `Copilot`, and its
addressable account name is `copilot-pull-request-reviewer[bot]`. That is a
different account from `copilot[bot]` (issue/PR comments) and
`copilot-swe-agent` (the Copilot coding agent used for issue/PR assignment) --
don't confuse them.

## Why the template uses two steps, not one

Because `gh pr create --reviewer "@copilot"` is undocumented in `pr create`'s
own help (as of 2.96.0) even though the underlying reviewer-alias translation
lives in code shared between `pr create` and `pr edit`. It may well work, but
guessing wrong burns a real PR on a real repo, so `foreman-instructions.md`
has the Foreman do it in two documented steps instead:

    gh pr create --base <default-branch> --head <feature-branch> \
                 --title "..." --body "..."
    gh pr edit <pr-url> --add-reviewer "@copilot"

A failing `--add-reviewer` is not a reason to abandon the PR or retry in a
loop -- the template tells the Foreman to note it and move on. It also
requires Copilot code review to be enabled for the repository/organization;
if it isn't, expect the request to be rejected or silently ignored depending
on your plan.
